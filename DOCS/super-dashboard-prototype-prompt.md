# Super Dashboard · React 快速原型实施提示词

将以下内容作为实施任务交给编码 agent。目标是交付可运行、可点击、可保存的个人工作台原型。

配套实施规划：[super-dashboard-prototype-plan.md](super-dashboard-prototype-plan.md)。交接时一并提供。该规划补充了页面布局、实体规则、示例数据、工作批次与验收场景；主提示词中的用户目标和范围仍然有效。规划中的默认值是本轮可调整的工程选择，不是已经由用户逐项确认的偏好。

---

你是这个原型的主实施工程师，同时负责交互设计、React 实现和浏览器验证。请直接完成可运行的工程，不要停在方案、静态截图或组件示例。执行中采用合理默认值；只有缺少必要信息而无法继续时才提问。

开始时通读配套规划，检查现有仓库是否需要适配，然后从第一批可交付切片开始。不要再生成一套重复 PRD、重新进行完整访谈或等待逐批审批。维护一份简短的实施状态即可。

## 1. 产品背景与本轮目标

用户 Sam 是有商业全栈经验、重视独立审美的 Builder。现在使用 Notion、Obsidian、散落的记事本、日记与房间白板记录项目和生活。信息分散带来寻找上下文、关联知识和继续行动的困难。

他想做一个本人长期使用的 Super Dashboard，可视化管理项目、学习、生活待办、阅读、练琴、健身、核心思考与日记。先本人 dogfooding，再按真实使用反馈生长。商业化只是未来可能性，本轮不做多租户、订阅、客户定制或团队协作。

本轮是快速交互原型：验证信息结构、视觉体验，以及项目与学习之间的关联。使用少量、可信、明确标记的示例数据，完成主要交互和本地保存。

**学习地图与项目管理是并列的核心功能。学习地图必须首版实现，拥有一级导航，并在首页占据显著位置。不能将其降为未来功能或一个统计卡片。**

用户在这个任务中说的 P0 表示当前最高优先级。不要套用旧 Project Architectural Grading Matrix 中 P0=玩具项目的定义，也不要用旧 SOP 的架构等级作为阻止实施的门槛。

## 2. 产品体验原则

- 打开后能迅速看清：正在推进什么、下一步是什么、为什么学某项技术、上次做到哪里。
- 新念头可以迅速收集，允许稍后整理；不要求每次输入都填写完整分类。
- 区分“计划学习”“有实践记录”和“已经掌握”。AI 不得替用户给能力排名。
- 书、音乐、运动和哲学有独立价值，不把所有内容转成 KPI、连胜天数、积分或人生总分。
- 采用平等、清楚、可恢复的反馈。避免羞耻式逾期提示、“落后同龄人”等比较文案。
- 默认中文，保留有用的技术英文；兼顾中文长标题与中英混排。
- 信息丰富但层级清晰，不做拥挤的指标墙。用真实内容组织布局。
- 用“示例数据”标识初始内容；示例项目状态、技术熟练度、书籍、曲目和运动记录都不代表用户真实经历。

## 3. 技术与工程边界

- 使用 React + TypeScript。新目录默认使用 Vite；若已有 React 工程，先检查并复用既有配置。
- 本轮只做前端和本地数据。无需后端、登录、数据库服务、真实 AI API 或外部账号连接。
- 不抓取用户的 Obsidian、Notion、日记或其他私人文件。资料入口可支持用户填写的链接；示例入口不要假装已经接通。
- 采用简单清楚的组件与状态组织；不为原型增加工作流框架、插件体系或多 agent 调度。
- 依赖按实际用途选择，优先复用已有依赖。不要为了地图默认引入复杂图引擎。
- 用统一的数据状态维护实体关联，不在不同页面复制相互漂移的数据。
- 运行命令、安装步骤和端口以实际工程为准，交付时给出已验证的启动方式。

- `/Users/samztz/.codex/skills/garan-style/SKILL.md`

### 设计语言

Garan / 迦蓝之堂风格：**Data on Paper**，像精密仪表信息印在温暖纸面上。使用纸色、深墨、细线、方形结构、克制的琥珀与氧化红。界面应有明确审美，干净、可读、适合长期使用。

不要做通用白色 SaaS 卡片墙、紫色渐变、玻璃拟态或黑客终端。不要复制游戏的素材、标识或专有界面。

```css
:root {
  --g-paper: #cdc9b4;
  --g-paper-deep: #c0bca6;
  --g-panel: #d6d2be;
  --g-ink: #45413b;
  --g-ink-soft: #767163;
  --g-ink-faint: #9b9684;
  --g-rule: #a9a48f;
  --g-amber: #a06a2c;
  --g-alert: #a8492f;
  --g-font-display: "Rajdhani", "Arial Narrow", sans-serif;
  --g-font-body: "Noto Sans SC", system-ui, sans-serif;
}
```

- tokens 集中管理；已有样式体系时映射到现有 theme，不另起平行体系。
- 小字号正文和关键操作使用足够深的墨色；柔和或浅色 token 不直接用于低对比度正文。必要时增加可读的语义 token。
- 默认方角、1px 分隔线、对齐网格和轻微色阶变化，用字号与留白建立层级。
- 每个主要视图选择两三种特征：`◇` 标记、细线分区、英文眉题、深墨反白主按钮。避免装饰堆叠。
- 数字使用 tabular numerals；正文不使用过宽字距。
- 英文短标签可宽字距，中文名称保持主要可读层级。
- 字体缺失时使用 fallback；不要让远程字体网络访问阻塞交付。
- 图标风格统一；动画克制，尊重 reduced motion。
- 不强制军事化文案。生活待办、健身和个人思考使用自然语言。
- 手机触控目标、键盘焦点与文字可读性优先于装饰。

## 5. 信息架构

实现以下一级入口，所有入口都必须有实际内容。桌面可采用窄侧栏与主工作区；移动端允许导航抽屉或合适的底部导航，不把所有入口挤成一排。

### A. 总览 / Overview

首屏以“项目推进”和“学习路线”作为两块主要内容，不以统计数字开场。

- 当前项目：名称、当前目标、状态、下一步；能进入项目详情。
- 学习焦点：本轮关注技术、学习理由、关联项目、当前经验与目标能力；能进入学习地图。
- 今日事项：生活待办与项目待办有清楚标识，支持完成与撤销。
- 正在继续：正在读的书、练的曲子、最近运动和最近记录，采用紧凑信息区。
- 核心锚点：显示一条已选核心文字，能进入 Kernel。
- 全局快速记录入口：先写内容，可选“想法 / 待办 / 日记”，允许不关联项目。

避免把首页设计成八个同等大小的盒子。桌面上项目与学习应先被看见，其余内容易于扫描。

### B. 项目 / Projects

用列表、分组或轻量看板展示近期项目。初始示例可使用用户提到的名称：漫剧、App 1、App 2、外贸；内容和进度标明示例。

项目详情至少包含：

- 为什么做 / 本轮目标。
- 状态：想法、进行中、暂停、已完成。
- 下一步和少量任务，支持增加与完成。
- 关联技术及每项技术在项目中的用途与目标能力。
- 相关记录、资料入口。

可以新增项目、修改状态和下一步，关联或取消关联技术。从关联技术跳到学习详情，再返回项目时保持合理上下文。

### C. 学习地图 / Learning Map —— 首版重点

必须回答以下问题：

1. 我的技术栈有哪些部分，分别进行到哪里？
2. 当前项目带来了哪些学习需求？
3. 哪些技术值得深入掌握，哪些目前用过、做过即可？
4. 技术之间有哪些前置关系？
5. 哪个项目或记录能支持我的经验判断？
6. 下一步具体学什么、通过什么实践验证？

提供两个共用数据源的视图：

- **地图视图**：按领域与依赖关系安排节点，可采用分栏路线图、SVG 连线或其他可读布局。首版不需要拖拽编排、自动力导向或无限画布。节点可选择，选中后突出直接前置与关联项目。
- **清单视图**：可搜索和按领域、项目、当前经验、目标能力筛选，适合精准查找和手机使用。

地图必须表达真实关系，不能只把技术名称随机放在画布上。连线明确标识为示例前置关系，未选中时避免视觉噪声；手机通过清单和详情保留等价信息，不依赖缩小整张图。

技术详情面板包含：

- 名称、领域、简短说明。
- **当前经验（本人自评）**：未接触、了解、跟随实践、独立使用、能解释取舍并排障。它是可修改的经验描述，不是 AI 认证。
- **本轮目标能力**：理解概念、能完成指定任务、能独立交付、能深入判断与排障；另有暂不投入选项。
- **学习状态**：待安排、进行中、暂停、已达到本轮目标。
- 为什么学、下一项具体练习、可选资源链接。
- 前置技术与相关技术。
- 关联项目与该项目要求；同一技术可以被多个项目以不同深度使用。
- 实践证据：项目链接、完成过的任务或技术日记。允许无证据时明确显示“尚未关联实践记录”。

支持新增技术条目、编辑经验与目标、调整学习状态、关联项目、添加简短实践记录。修改后总览、项目详情和学习地图同步更新。

不要使用“React 掌握 73%”这类无依据精度。可显示已完成练习数量、已关联项目数量等有定义的事实；如果没有分母，就不用百分比。

初始提供约 12–16 个技术节点与少量有方向的依赖，覆盖前端、数据、验证、发布及 AI/内容工作流。分类、经验与路线均为示例，并允许用户修改。不要把全部技术列成开工前必修课。

### D. 生活 / Life

覆盖生活待办、阅读、练琴和健身，先用同页分区或 tabs，避免过多页面。

- 待办示例：买菜、去银行办理事项、给客户打电话。支持新增、完成、撤销和可选日期。
- 阅读：书名、当前章节或位置、最近一条笔记，可更新阅读位置。
- 练琴：曲目、最近练习内容、下一次关注点，可记一条练习记录。
- 健身：日期、训练内容、可选时长与备注，可新增和修改记录。

默认日期按用户本地日期处理。缺少记录显示“尚未记录”，不能据此断言今天没有运动。无需营养、训练方案或健康评估。

### E. Kernel / 核心

呈现核心哲学、人格定义和个人锚点，界面安静、适合阅读。可按主题浏览、编辑文字、选择首页锚点。

可以使用本对话明确提供的句子：“一次执行失败只是数据，不是人格判决。”其余示例文字明确标为可替换占位内容，不编造用户的自我定义。

本轮编辑的是原型本地内容，不连接或修改真实 Vault 的 `00_Kernel`。

### F. 记录 / Journal

个人日记与技术日记共享时间线，通过类型筛选。

- 支持创建、编辑和查看记录，字段包括标题、正文、日期、类型。
- 技术记录可关联项目与技术；个人日记关联为可选。
- 按标题与正文搜索；提供简单日期排序。
- 普通 textarea 与清楚的阅读排版即可，不实现复杂富文本编辑器。
- 快速收集的想法也可在这里找到，并能转成待办或关联到项目；转换后不重复生成相同条目。

## 6. 数据关系与本地保存

使用稳定 ID 表达关联，至少包含：Project、Technology、ProjectTechnology、Task、JournalEntry、Book、PracticeEntry、WorkoutEntry、KernelEntry、Capture。

这是概念清单，不要求为每类建立服务或独立架构层。ProjectTechnology 保存项目对技术的用途与目标要求，避免一个项目覆盖全局或其他项目的学习目标。

- 轻量文本数据可用带版本号的 JSON + localStorage；复用合理的已有持久化方案也可以。
- 仅首次没有数据时加载示例；刷新不能重新覆盖用户修改。
- 捕获读取、解析、写入失败。无法保存时明确提示，并保留当前输入，不能假装保存成功。
- 提供 JSON 导出与导入。导出包含实体与关联；导入先校验版本和基础结构，再说明“替换本地数据”并确认。无效文件不覆盖当前数据。
- 重置示例数据必须确认；先提供导出入口。
- 不在界面声称云同步、加密、长期备份或生产级可靠性。用简短状态说明“原型数据保存在此浏览器，可导出备份”。
- 避免为原型加入自动知识推断、真实聊天导入和自动熟练度评级。

## 7. 首轮验收：必须能走通的体验

1. 总览中的学习区域与项目区域同等重要，学习地图有清楚的一级入口。
2. 从一个项目进入关联技术，修改本轮目标并添加实践记录，回到项目和总览能看到一致结果。
3. 学习地图可以切换地图/清单、筛选项目、选择技术、查看前置关系与经验依据。
4. 新增项目和技术后可建立关联，刷新后仍存在；不能只允许操作预置示例。
5. 新增生活待办，完成后可撤销；快速收集的内容可再次找回。
6. 更新阅读位置、添加练琴或运动记录后，相应摘要更新。
7. 写一条技术日记并关联项目和技术，在相关详情能访问该记录。
8. 修改本地 Kernel 锚点并展示在总览。
9. 导出后重新导入能恢复主要内容与关联；错误 JSON 不破坏已有数据。
10. 桌面与约 390px 手机宽度下可操作；键盘可访问导航、按钮、表单与详情面板，面板支持关闭和合理焦点恢复。

没有后端时不制造虚假的网络 loading。需要体现的状态是实际存在的空列表、筛选无结果、输入错误、保存失败和导入失败。

## 8. 实施与验证方式

先快速检查工程，再实现页面骨架与设计 tokens，随后优先打通“项目 ↔ 学习地图 ↔ 技术记录”这条主线，再补齐其他生活模块与本地导出。整个任务继续推进到上述首轮体验可用，不停在骨架阶段。

若需要缩减实现成本，优先简化地图布局、动效和富文本，不削弱学习地图的核心交互，也不把其他入口留成空白占位页。

验证实际构建和类型检查；使用浏览器走查主线，查看真实截图并修复布局、对比度、溢出与交互问题。自动化测试优先覆盖共享数据关联、持久化与无效导入等关键行为，不为所有静态组件堆测试。

至少检查桌面与手机两个视口。只报告实际执行的验证；工具不可用时明确未验证项。不要仅凭代码推断页面已符合 Garan 风格。

最终交付：

- 可运行的 React 工程与真实启动命令。
- 简短 README：功能、数据保存位置、示例数据说明、导入导出方式。
- 已实现内容、验证结果、仍存在的限制。
- 可用时给出预览地址和桌面/手机截图。
- 一段五分钟以内的试用路径，优先展示项目与学习的双向关联。

完成原型后，邀请用户反馈最影响使用的部分，再决定下一轮。不要自行扩展到商业化、全量资料迁移、复杂 PWA 同步或自动 agent 管理平台。
