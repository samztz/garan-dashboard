# Super Dashboard · 原型实施规划

与 `super-dashboard-prototype-prompt.md` 一起交给实施 agent。本文把产品意图转成可执行的默认方案，帮助减少返工；不要求先搭建完整管理流程。原型完成后根据用户实际试用修订。

## 01 产品判断与本轮假设

### 已明确的需求

- 个人自用，先 dogfooding；React，实现 Garan Style。
- 项目与学习地图是核心；生活、阅读、练琴、健身、Kernel 和日记都需要实际入口与交互。
- 技术学习要关联项目需求，区分目标深度、当前经验与实践证据。
- 目标包括减少信息散落、恢复上下文、接续行动，并保留创作与生活的空间。
- 本轮交付快速原型，不接真实私人数据源，不以商业化作为设计前提。

### 本轮采用的可调整假设

- 桌面用于全局浏览与整理，手机用于快速查看和记录；两端都能完成核心操作。
- 学习页默认呈现完整技术版图，选择项目后突出该项目涉及的技术。两种阅读方式共用一张地图和一套数据，避免预先二选一。
- 页面通过六个一级入口进入；全局提供快速记录与数据管理。
- 首页“当前关注”由用户选择，不由 agent 推断重要性；界面给建议数量，不设不可调整的硬上限。
- 保存明确提交，表单草稿与已保存数据分开。没有网络连接依赖时不做假的等待动画。
- 示例生活内容可被替换，不为用户推断作息、病情、技术水平或真实进度。

### 判断原型有用的三个观察

1. 用户能从首页进入一个项目，找到下一步，并定位相关技术与资料。
2. 用户能说明一项技术为什么学、要学到什么程度、有什么实践依据。
3. 用户离开后重新打开，仍能找回之前的记录和上下文。

这三项依靠试用观察，不做总分或虚构效率提升百分比。

## 02 范围与完成深度

| 能力 | 本轮做到 | 更后面的事情 |
|---|---|---|
| 项目 | 新建、编辑、状态、下一步、任务、关联技术与资料 | 工时、团队、客户门户 |
| 学习 | 全景/项目筛选、地图/清单、目标、自评、练习、证据 | AI 课程规划、自动评级、无限画布 |
| 日常 | 待办、阅读位置、练习记录、运动记录 | 复杂周期规则、日历同步、健康建议 |
| Kernel | 浏览、编辑本地副本、选首页锚点 | Vault 写回、自动哲学分析 |
| 日记 | 创建、编辑、搜索、项目/技术关联 | 富文本、附件上传、全文知识图谱 |
| 数据 | 浏览器保存、版本校验、JSON 导入导出、示例重置 | 云同步、账号、真实资料迁移 |

“较轻”的模块仍须可创建或编辑并保存，不能用 Coming Soon 或点击无效的按钮代替。地图首先清晰可读，复杂排版与动效让位于主线完整。

## 03 页面与导航约定

默认路由可用 `#/overview`、`#/projects`、`#/learning`、`#/life`、`#/kernel`、`#/journal`，减少静态预览的路由回退配置；已有路由体系时沿用。

项目筛选、技术详情 ID、地图/清单模式放在 URL 或同等可恢复的导航状态中。浏览器返回应恢复上一页筛选；失效 ID 显示“条目不存在”并提供返回入口。

### 桌面总览草图

```text
┌ 导航 ─────┬ 日期 / 当前视图 ─────────────── 快速记录 / 数据 ┐
│ 总览      │ 本轮关注                                      │
│ 项目      ├ 当前项目（约半宽） ─┬ 学习焦点（约半宽） ──────┤
│ 学习地图  │ 目标 / 下一步       │ 技术 / 目标 / 实践入口     │
│ 生活      │ 进入项目           │ 进入完整地图              │
│ 核心      ├ 今日事项 ──────────┴───────────────────────────┤
│ 记录      │ 生活事项 + 项目任务，保留来源标识               │
│           ├ 正在读 / 正在练 / 最近运动 / 最近记录 ──────────┤
│           │ 核心锚点                                      │
└───────────┴───────────────────────────────────────────────┘
```

- 首页不需要展示所有条目；提供“查看全部”，完整内容在对应页面。
- “今日”包括到期日为本地今天的事项或手动选入今天的事项；无日期事项仍可在待办页找到。
- 较早未完成的事项放在可展开的“待重新安排”，不铺满红色告警。
- 当前项目与学习焦点根据显式关注字段排序；最近更新只作为次级排序。
- 手机顺序：简短标题与快速记录 → 项目 → 学习 → 今日事项 → 继续与锚点。学习入口在首屏附近可见，不藏进更多菜单。

### 学习页草图

```text
学习地图             [搜索] [全景 / 选择项目] [地图 | 清单] [+ 技术]
──────────────────────────────────────────────────────────────
领域与状态筛选
┌ 技术地图 / 领域分区 ──────────────────┬ 技术详情 ────────────┐
│ 节点：名称、经验、当前目标、学习状态  │ 为什么学             │
│ 选中后显示直接前置关系与相关节点      │ 当前经验 / 目标       │
│ 项目模式突出需要的节点和前置节点      │ 下一步练习           │
│ 不相干关系淡出，状态不用颜色单独表达  │ 关联项目与各自要求   │
│                                      │ 实践记录与资料入口   │
└──────────────────────────────────────┴──────────────────────┘
```

- “领域”表示前端、数据、验证、交付、内容工作流等分类，不等于难度等级。
- “经验阶段”是用户自评，不由地图横纵位置暗示所有技术必须按一条顺序学习。
- 节点全部可点击，也可通过清单和键盘访问；选中节点有明显边界与标题反馈。
- 只有选中节点时显示其直接关系，默认全景避免连线交织。
- 非阻塞的“相关”关系与“建议前置”关系分开标注；前置是本轮学习路径建议，不声称所有开发者都必须这样学。
- 项目筛选可保留相关前置节点，用“前置参考”标注，避免误以为它也是项目的直接需求。
- 手机默认清单，技术详情打开为独立页面或全屏面板；保留前置与项目链接。
- 新增节点也必须进入地图布局，不以固定坐标写死初始技术。

### 其他页面的完成形态

| 页面 | 主内容 | 主要动作 |
|---|---|---|
| 项目 | 项目列表、当前目标、任务、技术要求、资料、相关日记 | 创建、编辑、关联技术、完成任务 |
| 生活 | 待办/阅读/练琴/健身四个 tab，使用文本和记录列表 | 新增、编辑、完成/撤销、更新位置 |
| Kernel | 主题目录与舒适行宽的正文 | 编辑本地文字、选首页锚点 |
| 日记 | 类型与搜索过滤、时间线、正文 | 新建、编辑、关联项目/技术 |
| 快速记录 | 内容必填，类型与关联可选 | 保存、稍后整理、转换为待办/日记 |
| 数据管理 | 本地保存状态、导出、校验后导入、重置 | 下载 JSON、选择文件、查看导入摘要 |

## 04 数据契约与事实来源

采用普通 TypeScript 类型和 JSON。一个共享状态容器与存储适配器足够；按功能组织组件，避免每个页面都读写 localStorage。

所有实体使用稳定 ID。通用字段为 `id`、`createdAt`、`updatedAt`、`origin: demo | user`；时间戳采用 ISO，日期字段使用本地日历日期 `YYYY-MM-DD`。不得用 UTC 截断推导用户的“今天”。

| 实体 | 最小业务字段与含义 |
|---|---|
| Project | name、purpose、currentGoal、status、nextAction、focused、resourceLinks |
| Technology | name、domain、summary、experience、personalTarget、learningStatus、whyLearn、nextExercise、focused、resourceLinks |
| ProjectTechnology | projectId、technologyId、usage、requiredTarget；组合唯一 |
| TechnologyRelation | sourceId、targetId、kind: prerequisite/related；前置边表示 source 建议先于 target |
| Task | title、projectId?、dueDate?、plannedDate?、completedAt?；无 projectId 表示生活待办 |
| JournalEntry | title、body、entryDate、kind: personal/technical、projectIds、technologyIds |
| Book | title、author?、positionText、status: reading/paused/finished、note |
| PracticeEntry | pieceTitle、entryDate、content、nextFocus、durationMinutes? |
| WorkoutEntry | entryDate、content、durationMinutes?、note |
| KernelEntry | title、body；首页选择由 settings.activeKernelId 保存 |
| Capture | body、kind: idea/todo/journal、projectId?、convertedTo? |
| Settings | activeKernelId、version；可保存少量展示偏好 |

建议根结构：`{ schemaVersion: 1, savedAt, entities: {...}, settings: {...} }`。导出包增加 `exportedAt`；UI 临时筛选、打开面板和未提交草稿不混入正式实体。

### 三个学习概念严格分离

- `experience`：未接触 / 了解 / 跟随实践 / 独立使用 / 能解释取舍并排障。
- `personalTarget` 和 `requiredTarget`：暂不投入 / 理解概念 / 完成指定任务 / 独立交付 / 深入判断与排障。
- `learningStatus`：待安排 / 进行中 / 暂停 / 已达到本轮目标。

个人目标与项目要求可以不同。全景显示个人目标；项目视图同时显示该项目要求。多个项目要求不自动合并成最高等级，也不自动修改用户自评。

实践证据直接复用技术日记：详情中的“添加实践记录”预填关联 ID，保存为一条 JournalEntry。项目、技术与日记页面查询同一条记录，不另建一份镜像笔记。完成项目或任务不自动提升技术熟练度。

练琴首版不额外建立曲库：最新 PracticeEntry 的曲目和 nextFocus 构成首页摘要，历史按曲名可浏览。以后确有乐谱管理需求再扩展。

## 05 交互规则与异常处理

| 动作 | 明确行为 |
|---|---|
| 保存表单 | 必填内容去除首尾空格后非空；保持用户输入的正文格式；成功后更新共享状态与保存反馈 |
| 关闭未保存表单 | 有改动时允许“继续编辑 / 放弃”；验证失败或存储失败不丢输入 |
| 添加技术 | 名称不分大小写的重复项提示打开已有条目；不静默生成同名节点 |
| 关联技术与项目 | 重复关联更新既有关系；取消关联只移除关系，不删除技术、项目或历史日记 |
| 添加前置关系 | 禁止自连接、重复边和前置环；相关关系允许双向语义但只存一次 |
| 完成任务 | 设置 completedAt；撤销后清空。无项目任务和项目任务使用同一种数据 |
| 快速记录转换 | 创建目标实体并写入 convertedTo 作为一次状态变更；重复点击定位已有目标，不重复生成 |
| 项目状态变化 | 不自动完成全部任务，不清除记录；暂停或完成的项目默认退出首页当前关注，可从项目列表找回 |
| 空状态 | 有明确创建入口；筛选空结果提供清除筛选，不假称资料不存在 |
| 无效资料链接 | 说明允许的协议和格式。外部入口默认仅允许 http/https/obsidian；拒绝 javascript/data 等可执行输入 |
| 删除 | 首版可省略实体删除。若提供，必须说明关联影响并确认；不得留下悬空引用或级联删除日记 |

### 持久化边界

- 存储 key 使用专属名称，例如 `garan-dashboard:prototype:v1`，避免覆盖其他应用。
- 初始 key 不存在时播种 demo；值为空或损坏时进入恢复界面，不自动重置成 demo。
- 写入失败时显示“尚未保存”，保持编辑草稿/内存内容并允许重试或导出。必须区分内存可见与刷新后可恢复。
- 导入解析后检查 schemaVersion、必需字段、合法枚举、日期、ID 唯一性、关系引用和前置环。未知的新版本拒绝导入并解释，不自动猜迁移。
- 导入预览展示各类条目数量，明确本轮为替换而非合并。用户确认后作为一个整体保存；写入失败不能替换当前有效状态。
- 不在关闭页面时才保存。正式保存操作应立即尝试持久化；不能显示虚假的自动云同步状态。
- 检测其他标签页修改本地数据时提示重新加载，并保护当前草稿；首版不实现自动合并，但避免旧标签悄悄覆盖新版本。
- 重置前导出可选，必须确认；取消导入或重置保持原数据。
- 不渲染任意 HTML。日记用文本展示；即使后续支持 Markdown，也避免未清洗的 HTML 执行。

## 07 工程组织与实施批次

沿用现有 React 工程的约定。新工程可以采用如下最小结构，不要求逐项创建空目录：

```text
src/
  app/            # shell、导航、共享 store
  domain/         # 类型、状态变更、查询、导入校验
  data/           # demo、存储适配
  features/       # overview、projects、learning、life、kernel、journal
  ui/             # 实际复用的按钮、字段、面板等
  styles/         # Garan tokens 和基础样式
```

共享状态可采用 reducer + context，已有轻量状态库时复用。跨页面汇总通过 selector 派生，不把“技术关联项目数”“首页最近记录”等重复存储。

| 批次 | 实施内容 | 退出证据 |
|---|---|---|
| 1. 可用主线 | Garan shell、真实 demo、项目详情、学习清单、技术详情、实践记录、基础保存 | 项目→技术→新增记录→返回→刷新，关联与内容一致 |
| 2. 可读地图 | 领域布局、前置/相关关系、项目筛选、搜索、详情、手机替代视图、首页学习焦点 | 新增技术也能显示；项目筛选关系正确；宽窄屏可读 |
| 3. 完整工作台 | 生活四区、Kernel、日记、快速收集与转换、首页汇总 | 每类内容有真实编辑闭环，无空壳入口 |
| 4. 可交接原型 | 导入导出、数据恢复状态、多标签保护、视觉修正、关键检查、README | 验收表通过，真实启动方式和未验证项清楚 |

批次是执行顺序，不是等待用户逐批审批的关卡。每批完成后更新一份简短状态记录：已完成、验证、下一步、阻塞。除非用户改变范围，继续完成全部批次。

先实现普通清单与主线，再做地图的视觉增强，这能让布局问题不阻塞数据交互。首批就应用 Garan tokens，避免最后整站换肤。

| A05 | 添加 A→B，再尝试 B→A 前置关系 | 明确解释环路并拒绝第二条；已有合法关系保留 |

| A07 | 新建生活待办，完成后撤销 | 今日与生活页一致；日期按本地日历 |
| A08 | 连续点击快速记录“转待办” | 仅产生一个 Task，可从原记录定位目标 |
| A09 | 更新书的位置、写练琴/运动记录 | 正确更新摘要与历史；无记录日期显示尚未记录 |
| A10 | 编辑 Kernel 并选为首页锚点 | 首页准确展示，本地刷新保留；不访问 Vault |
| A11 | 导出，修改，再导入导出文件 | 确认替换后恢复实体与关联，取消导入不改变数据 |
| A12 | 导入错误 JSON、新版本、重复 ID 或悬空引用 | 提示明确原因，当前数据不变 |
| A13 | 模拟存储写入失败 | 不显示已保存，输入仍在，可重试/导出；不静默重置 |
| A14 | 两个标签页先后编辑 | 后一个检测到更新并提示；不无提示覆盖，草稿可保留 |
| A15 | 关闭有修改的详情表单；取消放弃 | 保留输入与焦点；无编辑时直接关闭 |
| A16 | 桌面、390px、320px 宽度浏览 | 主操作可用，无页面级横向溢出；地图有清单替代 |
| A17 | 键盘访问导航、节点列表和对话框 | 可见焦点，ESC 关闭合适面板，关闭后焦点返回触发处 |
| A18 | reduced motion 与长中文内容 | 非必要动效停止；文本不遮挡操作；主题对比可读 |

## 09 最容易返工的地方与处理顺序

| 风险 | 提前处理方式 |
|---|---|
| 地图漂亮但不能管理学习 | 先打通清单、目标、项目关系与证据；地图读取同一数据 |
| 主项目要求覆盖个人目标 | 明确 ProjectTechnology 与 Technology 的字段边界 |
| 八个模块各自一份数据 | 单一状态源，首页与详情使用派生查询 |
| UI 很完整但按钮无效 | 每个可见主动作对应状态变化或导航，未实现动作不伪装可用 |
| 新增条目破坏固定布局 | 用动态分组与稳定排序，不硬编码 demo 节点坐标 |
| 示例被当作真实进度 | demo 来源标识持续可见，不生成真实能力结论 |
| 原型开始使用后丢记录 | 基础保存早于复杂动效，失败反馈和导出进入最终验收 |
| Garan 色板造成小字难读 | 深墨用于正文，弱色用于装饰；实际浏览器检查对比 |
| 文档量超过实施收益 | 复用本包，只维护 README 和简短实施状态；新增决定记几行即可 |

需要缩减成本时，依次减少：装饰纹理和动效 → 地图连线复杂度 → 排序方式数量 → 高级编辑能力。保留新增/编辑、本地保存、项目学习关联和主要生活记录能力。

## 10 五分钟试用与反馈

1. 首页看项目与学习焦点，进入 App 1。
2. 打开 React，看它在两个项目中的不同要求。
3. 修改本轮个人目标、添加一条实践记录，回日记查看，再刷新。
4. 新建一条买菜待办，更新一次阅读位置，写一条练琴记录。
5. 查看学习全景与项目筛选，切到手机宽度，再导出数据。

试用后优先问三个问题：打开后是否知道下一步；学习地图是否帮助判断投入深度；哪项记录最难找到或最不愿意填写。保留对审美和交互的主观反馈，不把反馈变成能力评价。

原型结果应提供清楚证据：代码、运行入口、真实截图、验证记录、已知限制。进入下一轮前依据试用选择最重要的调整，不自动继续增加模块。
